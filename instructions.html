1 Overview

The FHI Rate Card is a self-contained pricing component used to advertise Internet / TV / Phone subscription plans. It is fully configurable (badge, headline, prices, specs, features, CTA, colours) and behaves consistently between desktop and mobile breakpoints.

This document captures every visual and behavioural decision the component relies on. It assumes the target codebase uses AngularJS 1.8.2, but the markup and styles are framework-agnostic.

Important — read first The right-side configurator panel on the live page is not part of the production component. It demonstrates which fields the CMS admin panel should expose for editors (text content, colours, prices, features, visibility toggles, etc.). When integrating into the CMS, every input shown in that panel should become a corresponding field in the component's admin form.
Default visibility of “See price journey” In production, the See price journey toggle bar should be hidden by default. It is only shown when an editor explicitly enables it from the admin panel. The on-by-default state in the live preview exists for design review only. See dedicated Price Journey section below.

Key characteristics

  • Single column, fixed width 411px on desktop, fluid 92vw on mobile.
  • Two collapsible sections: Price Journey (hidden by default in production — opens when enabled by the editor; contains an optional summary banner) and what's included (always rendered, closed by default).
  • One static panel: internet specs — always visible, never collapsible.
  • One primary action: the orange CTA button with full-fill black hover.
  • One legal footer at the very bottom.

Reading order for this guide

Sections are ordered to onboard a developer in the same order they will need information:

  1. Anatomy — what the card is made of, visually.
  2. Price Journey — the most complex region, isolated up front so it doesn't get lost.

2 Quick start

Drop the component into any AngularJS 1.8.2 view. Three prerequisites: load AngularJS + angular-sanitize, include the custom font, and wrap the markup in an ng-app + RateCardCtrl as vm controller. The complete canonical model is documented in §12.2; the snippet below shows only the minimal shape.

1. Load the dependencies

html 
<script src="https://ajax.googleapis.com/ajax/libs/angularjs/1.8.2/angular.min.js"></script>
<script src="https://ajax.googleapis.com/ajax/libs/angularjs/1.8.2/angular-sanitize.min.js"></script>
ngSanitize is mandatory The feature pills (check / plus / star / shield / wifi) inject inline SVG via ng-bind-html, which requires $sce.trustAsHtml + angular-sanitize. Do not add angular-animate — accordion motion is pure CSS.

3 Component anatomy

The card is composed of five vertically stacked regions inside a single .pricing-card container.

  1. Card header — dark navy gradient. Contains the plan badge, the orange headline (48px desktop / 32px mobile), the price block (original price, hero price at 64/48px, period, price note, savings badge with the price-tag pictogram).
  2. Price Journey toggle + body — collapsible horizontal timeline of pricing steps with an optional summary banner underneath (hidden by default in production). See the dedicated Price Journey section.
  3. Internet specs panel — three rows with circular icons (download / upload / unlimited).
  4. What's included toggle + body — collapsible list of selling points with check or plus icons (closed by default).
  5. Footer — CTA button + legal note.
Container constraints The whole card sits inside a .card-stage wrapper centered on the viewport. The card itself has overflow: hidden so child sections never bleed past the 20px border-radius.

4 Price Journey

The Price Journey is a collapsible horizontal timeline that shows how the plan price evolves over time. It replaces the legacy “price breakdown” table. Each pricing period is a rounded card, separated by an orange chevron ›. An optional summary banner sits underneath. Editors compose everything from the CMS.

Production default The Price Journey is wrapped by a toggle button (“See price journey”) and is hidden by default. Surface it only when an editor enables it from the admin panel.

4.5 Interaction model

  • The accordion uses a max-height transition (see §Motion) — 0.85s open / 0.7s close, easing cubic-bezier(0.65, 0, 0.35, 1).
  • aria-expanded flips on the toggle button; the arrow pictogram rotates 180° over 0.6s.
  • Repeater controls (+ Add step / ×) are CMS-only and never rendered in production.
  • Adding or removing steps must not break the layout — the row uses display: flex with flex: 1 per step.
  • The summary banner is independent of the step list — editors can hide it without removing any step.

4.6 CMS fields to expose

  1. Show Price Journey — boolean, default OFF.
  2. Toggle label — string, default “See price journey”.
  3. Header title — string, default empty.
  4. Savings text — free-text string (the entire phrase, not just the number), default “Save $240/year”.
  5. Steps — repeater of { period, price, tag, subtext, style } objects.
  6. Show summary banner — boolean, default ON.
  7. Summary banner text — string, default “Free for 3 months, then $39/mo. through month 12, then $45/mo. ongoing.”

7 Responsive behavior

The component has one breakpoint: 480px. Below this width, the card switches to fluid width and several font sizes shrink. Layout, vertical rhythm and section order do not change between breakpoints.

Mobile-only overrides

css 
@media (max-width: 480px) {
  .pricing-card { width: 92vw; }
  .legal-note { font-size: 12px; }

  /* Body text shrinks to 14px */
  .period,
  .breakdown-toggle,
  .specs-title,
  .speed-item,
  .features-list li,
  .cta-button { font-size: 14px; }

  /* Tighter elements shrink to 12px */
  .savings-label,
  .price-note,
  .journey-savings,
  .journey-summary { font-size: 12px; }

  .step-period,
  .step-subtext,
  .step-tag { font-size: 12px; }

  /* Marketing hero overrides */
  .plan-headline { font-size: 32px !important; }
  .amount { font-size: 48px; }
}
Why !important on .plan-headline? The headline size is set inline (style="font-size: 48px") by the CMS slider, which would normally beat any CSS rule. The !important at the mobile breakpoint guarantees 32px on phones regardless of the editor's desktop choice.

8 Motion & transitions

Motion in the card is intentionally restrained. Only the accordions (Price Journey, What's included), the CTA hover, the chevron rotation and a handful of UI states animate. Everything else is static.

8.1 Accordion (Price Journey + What's included)

Both accordions share the same CSS class .price-breakdown-section and animate by transitioning max-height between 0 and 600px. The closed/open states use different durations on purpose — opening reads as “unfolding”, closing reads as “tidying up” and feels faster.

StatePropertyDurationEasing
Closingmax-height0.7scubic-bezier(0.65, 0, 0.35, 1)
Openingmax-height0.85scubic-bezier(0.65, 0, 0.35, 1)
Arrow rotationtransform0.6scubic-bezier(0.65, 0, 0.35, 1)
css 
.price-breakdown-section {
  max-height: 0;
  overflow: hidden;
  transition: max-height 0.7s cubic-bezier(0.65, 0, 0.35, 1);
}
.price-breakdown-section.open {
  max-height: 600px;
  border-bottom: 1px solid #e5e5e5;
  transition: max-height 0.85s cubic-bezier(0.65, 0, 0.35, 1);
}

.breakdown-toggle .arrow {
  transition: transform 0.6s cubic-bezier(0.65, 0, 0.35, 1);
}
.breakdown-toggle.active .arrow { transform: rotate(180deg); }
Why this curve? cubic-bezier(0.65, 0, 0.35, 1) is an easeInOutCubic — the motion starts softly, accelerates through the middle, and decelerates smoothly to a stop. It avoids the “snap-open / snap-close” feel of ease-out on a max-height transition.

8.2 CTA button hover

The CTA fills with solid black from the bottom up using a pseudo-element animating height from 0% to 100%. Text colour cross-fades to white at the same time.

8.4 Reduced motion

If the user has expressed a preference for reduced motion, all transitions should be neutralised. Add this at the bottom of the stylesheet:

css 
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
  }
}
Do NOT animate Layout-affecting properties other than max-height on the accordions, fonts, or anything that triggers a full reflow. Stick to opacity, transform, color, background and the specifically listed max-height / height animations above.

11 Interactive states

State semantics for each interactive surface. Timing details for transitions live in §8 Motion.

11.1 Price Journey toggle

  • Production default: the whole See price journey section (toggle bar + body) is hidden. It is only rendered when the CMS editor enables it via the Show Price Journey field.
  • Closed: no .active on the toggle, no .open on the body. Arrow points down. aria-expanded="false".
  • Open: toggle gets .active; body gets .open (which sets max-height: 600px). Arrow rotates 180°. aria-expanded="true".

11.2 What's included toggle

  • Always rendered, closed by default.
  • Same state pair as Price Journey (.active on toggle, .open on body), same transitions.
  • aria-expanded stays in sync with the visual state.

11.3 CTA button

  • Rest: orange background (#ed6b1f), white text, weight 700.
  • Hover: pseudo-element fills from bottom up with solid black (#000), text stays white.
  • Focus: default browser ring — do not outline: none without a replacement.
  • Active (press): no custom state; the browser default is acceptable.
css 
.cta-button {
  position: relative;
  overflow: hidden;
  background: #ed6b1f;
  color: #fff;
  transition: color 0.3s ease;
}
.cta-button::before {
  content: '';
  position: absolute;
  bottom: 0; left: 0; right: 0;
  height: 0;
  background: #000;
  transition: height 0.3s ease;
  z-index: -1;
}
.cta-button:hover::before { height: 100%; }
.cta-button:hover { color: #fff; }

11.4 Visibility utility (.hidden-el)

Every editor toggle in the panel — savings, original price, headline, specs, legal, summary banner, Price Journey, etc. — maps to a single CSS utility class:

css 
.hidden-el { display: none !important; }

This keeps the markup stable. The directive / controller adds or removes the class according to the bound boolean. There is no other visibility mechanism in the component.

11.5 Floating UI buttons (developer-only)

The gear (configurator), docs and stories buttons in the preview page are developer affordances. They must not ship to production embeds of the rate card. Their styles and transitions live in the same file only for the preview experience.

12 AngularJS 1.8.2 integration

The component is plain HTML/CSS — AngularJS 1.8.2 drives three things only: (a) data binding from the CMS model (vm.plan), (b) the .active / .open classes on the accordion toggles, and (c) the visibility booleans that toggle the .hidden-el utility. Everything else (motion, layout, hover) stays in CSS.

Dependencies AngularJS 1.8.2 · angular-sanitize 1.8.2 (mandatory — required by ng-bind-html for inline SVG). No other Angular modules are needed; do not add angular-animate — accordion motion is pure CSS.
Pattern used: controllerAs vm The shipped reference (template.html) binds via ng-controller="RateCardCtrl as vm". All examples below assume that alias. If you prefer the legacy $scope pattern, swap every vm. for $scope. and inject $scope into the controller — the markup remains otherwise identical.

12.1 Module bootstrap

javascript

12.5 Performance & digest discipline

  • track by $index — Required on both ng-repeats (steps, features) to keep DOM nodes stable when an editor reorders or replaces items.
  • No $watch on the model — Don't add manual watchers. The whole card re-renders on the next digest whenever vm.plan mutates; that is enough.
  • No $apply calls — All state changes happen inside Angular's digest (ng-click, ng-change, ng-model). Adding manual $apply will throw "$digest already in progress".
  • Optional optimisation — one-time bindings ({{::expr}}) — When the CMS payload is loaded once and never mutates, prefix every value-only binding with :: (e.g. {{::vm.plan.badge}}). This stops the watcher after the first stable digest and trims ~30 watches off the card. Do not apply this in the shipped template.html: the live configurator mutates vm.plan via ng-model, and one-time bindings would freeze it.
Rule of thumb Use plain bindings (as in §12.4) anywhere the model can be re-assigned in-place (CMS preview, A/B test variant swap, live editing). Use :: only when you can guarantee the bound expression is stable after first render.

12.8 Gotchas specific to AngularJS 1.8.2

  • SVG + ng-bind-html — Without ngSanitize loaded, inline SVG strings render as text. Always load angular-sanitize and pipe through $sce.trustAsHtml as in §12.3.
  • aria-expanded — Use ng-attr-aria-expanded="{{ vm.ui.journeyOpen }}", not plain aria-expanded="{{...}}". The ng-attr- prefix prevents the browser from reading the literal {{...}} before the first digest.
  • Inline styles vs. CSS classes — Editor-controlled colours (badge background, headline colour, CTA, header gradient) use ng-style. Editor-controlled visibility uses ng-class with .hidden-el. Never mix the two; display: none in inline styles will fight the CSS animation on the accordions.
  • Repeater + chevron pattern — The chevron between journey steps is rendered with ng-repeat-start / ng-repeat-end so the chevron and the step share the same iteration. Do not author chevrons in the data — the front-end inserts them.
  • type="range" + ng-model — Angular returns a string from a range input. The shipped template handles this by string-concatenating + 'px' inside ng-style; if you need a true number elsewhere, coerce with parseInt or use type="number".
  • Digest budget — A single card with three features and three journey steps produces roughly 40 watches. Multiple cards on a page can compound — paginate or virtualise listings if you ship more than 6 cards in a single view, and/or apply the :: optimisation from §12.5.

13 Data I/O (configurator)

The configurator side-panel exposes a Data I/O section at the bottom that lets a designer, PO, or dev round-trip the card payload as JSON — without writing code. Three primary actions: export the current card, import an existing JSON, or download an annotated empty template (with a field mapping for the dev team). Everything in this section lives only in the configurator; the production rate card does not need any of it.

Where it lives in template.html. Markup: the .config-section with vm.ui.sections.dataIo toggle, just above the Reset to defaults button. Controller: methods grouped under Data I/O actions, plus helpers (setStatus, isValidPlan, downloadBlob, timestamp). One supporting directive: fileOnChange.

13.1 The five actions

  • Generate JSON — vm.exportJson(). Serialises vm.plan with JSON.stringify(…, null, 2), mirrors it into the textarea (vm.io.exportText), and triggers a download as fhi-rate-card-{YYYYMMDD-HHMMSS}.json.
  • Upload JSON — vm.triggerImport() programmatically clicks the hidden <input type="file">. The fileOnChange directive (see §13.5) forwards the picked file to vm.handleImportFile($files), which reads it with FileReader, parses, validates, and assigns to vm.plan.
  • Download empty template — vm.downloadTemplate(). Bundles three blocks (_about, _mapping, plan) and downloads them as fhi-rate-card-template.json. The dev fills the file offline and re-uploads it.
  • Copy JSON — vm.copyJson(). Pushes the textarea content to the system clipboard via navigator.clipboard.writeText(). Falls back to an explicit error message if the API is unavailable or the browser blocks it.
  • Apply pasted JSON — vm.applyPastedJson(). Same parse + validate + assign pipeline as Upload JSON, but reads from the textarea — useful when you want to paste a payload (e.g. a CMS response) directly without saving a file first.

Every action ends by calling setStatus(message, type), which populates vm.io.status + vm.io.statusType (success / error / info). The status div under the action buttons reflects the latest outcome.

13.3 Import validation

Before replacing vm.plan, the candidate is run through a structural check. If the check fails, the existing plan is kept untouched and the status area shows a precise error.

function isValidPlan(p) {
  return p
    && typeof p === 'object'
    && typeof p.badge        === 'string'
    && typeof p.headline     === 'string'
    && typeof p.currentPrice !== 'undefined'
    && p.headerGradient && typeof p.headerGradient === 'object'
    && p.cta && typeof p.cta === 'object'
    && Array.isArray(p.features);
}

This is intentionally minimal — the goal is to stop a totally wrong file from blanking the card, not to enforce a full schema. If you need stricter validation (e.g. for a public-facing CMS endpoint), extend isValidPlan rather than wrapping it.

13.4 Adding a new field to the model

When you extend vm.plan with a new field, keep the template in sync by touching three places in template.html:

  1. Add the default value to defaultPlan() so the live preview and the downloaded template both ship it.
  2. Add an entry to MAPPING_DOC with a one-line type · description. Use the same dot-path convention as existing entries (e.g. 'specs.download.value', 'features[].icon').
  3. If the field is required for the card to render meaningfully, add a check inside isValidPlan(). Optional fields don't need a guard.

Doc sync reminder. Also update the CMS field-to-binding map in §12.7 so the table and the downloadable mapping stay in agreement — they target the same audience.

13.5 Implementation notes

  • Preview-only. The entire .data-io-* CSS block, the Data I/O .config-section, the vm.io state, every vm.{exportJson, copyJson, triggerImport, applyPastedJson, handleImportFile, downloadTemplate} method, the four helpers, and the fileOnChange directive are all safe to delete in production along with the rest of the configurator.
  • Why a directive for the file input. AngularJS 1.x does not bind ng-model to <input type="file">. The shipped fileOnChange directive listens for the native change event, then re-enters the Angular digest with scope.$apply and forwards the file list as a local $files binding — idiomatic usage is file-on-change="vm.handleImportFile($files)".
  • Why $timeout. FileReader callbacks and the navigator.clipboard Promise resolve outside Angular's digest. Wrapping the resulting state mutation in $timeout(…) schedules a digest so the textarea, status message, and card all re-render.
  • File download primitive. The shared downloadBlob(filename, text) helper creates a Blob, exposes a transient object URL, clicks a synthetic <a download>, then revokes the URL on the next tick. This is the only place the rate card markup performs an explicit DOM lookup; production embeds drop it with the rest of the configurator.
  • Re-selecting the same file. vm.triggerImport resets input.value = '' before opening the picker so picking the same filename twice still fires the change event.
  • Accepted MIME / extension. The input declares accept="application/json,.json". The browser hint is non-binding — parsing happens defensively in vm.handleImportFile.

14 Accessibility

  • Semantic toggles: the collapsible bars are <button> elements with aria-expanded kept in sync with the open/closed state via ng-attr-aria-expanded.
  • Decorative SVG: all pictograms carry aria-hidden="true" — they sit next to descriptive text, so they do not need an explicit label.
  • Focus ring: all interactive elements expose the default focus ring; do not outline: none without an equivalent :focus-visible style.
  • Colour contrast (WCAG AA): orange CTA on white passes 4.5:1. White text on the navy gradient header passes 7+. Summary banner text (#5d3a1a on #fff7f0) passes 7+. Step periods/subtexts on the active blue background pass 4.5+.
  • Reduced motion: the accordion durations (0.7–0.85s) and CTA hover (0.3s) are non-essential — apply the prefers-reduced-motion guard from §8.4.
  • Form-only fields: if the CTA becomes a form submit, ensure the surrounding <form> exposes a meaningful aria-label (e.g. "Subscribe to Internet 1G plan").
